# Sweet Lab Orders — المرحلة الأولى

منصة طلبات معمل حلويات يورد لعدة محلات وكافيهات. هذه المرحلة تبني الأساس: قاعدة البيانات، الصلاحيات، الدخول، اللغتين، وقالب التنقل لكل دور. التفاصيل الكاملة في [`docs/architecture.md`](docs/architecture.md).

**التقنية:** Next.js 15 + TypeScript، Tailwind CSS، next-intl، Supabase (Postgres, Auth, Realtime)، النشر على Vercel.

## التشغيل محلياً

المتطلبات: Node 20.6+ و Docker (لـ Supabase المحلي).

```bash
npm install
npm run db:start          # يشغل Supabase محلياً ويطبق migrations
cp .env.example .env.local
# انسخ API URL و anon key و service_role key من مخرجات الأمر السابق إلى .env.local
```

إنشاء أول مشرف عام (مرة واحدة):

```bash
# ضع BOOTSTRAP_ADMIN_PASSWORD في .env.local (12 حرفاً على الأقل)
npm run bootstrap:admin -- owner@your-lab.com "اسم المشرف"
# ثم احذف BOOTSTRAP_ADMIN_PASSWORD من الملف
```

```bash
npm run dev               # http://localhost:3000 ← يوجه إلى /ar/login
```

لإنشاء حسابات تجربة للأدوار الأخرى قبل بناء شاشة المستخدمين: من Supabase Studio (`http://127.0.0.1:54323`) ← Authentication ← Add user، ثم في SQL Editor:

```sql
-- حساب معمل
update auth.users set raw_app_meta_data = raw_app_meta_data || '{"role":"kitchen_staff"}' where email = 'kitchen@your-lab.com';
update public.profiles set role = 'kitchen_staff', is_active = true where id = (select id from auth.users where email = 'kitchen@your-lab.com');

-- حساب عميل: أنشئ المحل أولاً ثم اربطه
insert into public.customers (name_ar, name_en) values ('اسم المحل', 'Shop name') returning id;
update public.profiles set customer_id = '<customer-id>', is_active = true where id = (select id from auth.users where email = 'shop@example.com');
```

## الاختبار

```bash
npm run test:i18n   # الترجمتان متطابقتان وكل أخطاء القاعدة مترجمة
npm run typecheck
npm run db:test     # 22 اختبار pgTAP: عزل العملاء، منع الكتابة المباشرة، القفز بين الحالات،
                    # الإرسال المكرر، الطاقة الإنتاجية، تنبيه المعمل بالتعديل، سجل التدقيق
```

قائمة الفحص اليدوي قبل اعتماد المرحلة:

- [ ] `/` يوجه إلى `/ar/login`، وأي صفحة محمية بدون دخول توجه للدخول ثم تعود إليها بعده.
- [ ] رسائل التحقق تظهر تحت الحقل بالعربية والإنجليزية (بريد فارغ، بريد خاطئ، كلمة مرور خاطئة).
- [ ] الزر يتعطل أثناء الدخول (لا إرسال مزدوج).
- [ ] حساب غير مفعّل يظهر له "الحساب غير مفعّل" ولا يدخل.
- [ ] كل دور يصل لواجهته فقط: العميل يكتب `/ar/admin` يدوياً فيُعاد لـ `/ar/customer`.
- [ ] `/admin/users` يفتح للمشرف العام فقط.
- [ ] زر English/العربية يقلب الاتجاه فوراً، ويبقى بعد الخروج والدخول مرة أخرى.
- [ ] واجهة المعمل على آيباد: الشريط العلوي والأزرار مريحة للمس، والساعة بتوقيت الرياض.
- [ ] افصل الإنترنت: يظهر شريط "لا يوجد اتصال"، وعند العودة "عاد الاتصال".
- [ ] أعداد الحالات في الرئيسية تتغير فوراً عند تغيير طلب من حساب آخر (بدون تحديث الصفحة).
- [ ] الوضع الداكن للجهاز يعمل، والواجهة سليمة على عرض 375px.
- [ ] يمكن تثبيت التطبيق من المتصفح (PWA).

## النشر على Vercel

1. أنشئ مشروع Supabase واربطه: `npx supabase link --project-ref <ref>` ثم `npx supabase db push`.
2. في Supabase ← Authentication ← Providers ← Email: أوقف **Allow new users to sign up**، واضبط Site URL على رابط Vercel.
3. في Vercel أضف `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` فقط. **لا تضف مفتاح الخدمة.**
4. شغّل `bootstrap:admin` من جهازك مرة واحدة على مشروع الإنتاج.

## ما تم في المرحلة الأولى

- هيكل المشروع وإعداد Next.js وTailwind وnext-intl وSupabase.
- قاعدة البيانات كاملة: العملاء والفروع، المستخدمون والأدوار، المنتجات والتصنيفات، الطاقة الإنتاجية وأيام الإغلاق وفترات التسليم، الإعدادات، الطلبات وبنودها وسجل التدقيق.
- سياسات RLS حقيقية لكل الجداول، ومنع الكتابة المباشرة على الطلبات.
- منطق دورة الطلب في القاعدة: الإنشاء بلا تكرار، التعديل مع تحكم بالتزامن، مصفوفة الانتقالات، السبب الإلزامي، تنبيه المعمل بالتعديل، التحقق من التاريخ ووقت الإغلاق وزمن التجهيز والطاقة بتوقيت الرياض.
- Realtime مفعّل على الطلبات وسجلها.
- تسجيل الدخول والخروج، حماية المسارات، حارس الدور لكل منطقة، حفظ اللغة المفضلة.
- العربية (افتراضي RTL) والإنجليزية (LTR) لكل النصوص والحالات والأخطاء.
- قالب تنقل لكل دور: شريط جانبي للإدارة والعميل على الشاشات الكبيرة، أزرار أفقية على الجوال، شريط علوي كبير للمعمل.
- شريط انقطاع الاتصال، تحديث فوري للأرقام، PWA قابل للتثبيت، وضع داكن.
- اختبارات pgTAP وفحص الترجمة.

## ما تبقى (المرحلة الثانية فما بعد)

- نموذج الطلب للعميل ومتابعة الطلبات وإعادة الطلب.
- شاشة اعتماد الطلبات للإدارة مع عرض الفروقات عند التعديل.
- لوحة المعمل التفاعلية ببطاقات إنتاج كبيرة وتنبيه صوتي للطلبات الجديدة والتعديلات.
- جدول الإنتاج اليومي والأسبوعي من عرض `production_plan`.
- شاشات المنتجات والعملاء والإعدادات وإدارة المستخدمين (دعوة الحسابات عبر Server Action بمفتاح خدمة خادمي).
- اختبارات واجهة E2E (Playwright) للأدوار والترجمة.
- لاحقاً: الأسعار والفواتير، المخزون، إشعارات واتساب.
